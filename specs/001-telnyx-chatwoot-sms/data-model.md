# Data Model: Telnyx ↔ local Chatwoot SMS Bridge

**Database**: PostgreSQL 16  
**Access layer**: Kysely  
**Privacy baseline**: SMS body never persists as plaintext; canonical phones are encrypted and indexed by keyed HMAC.

## Conventions

- Primary keys are UUIDv7/UUID generated by the application unless a provider integer/string ID is the natural external key.
- All timestamps are `timestamptz` in UTC.
- State values are PostgreSQL text columns constrained by `CHECK`; application types mirror them as TypeScript unions.
- Full phone numbers never appear in logs or audit payloads.
- Provider payload ciphertext uses AES-256-GCM. The implementation may store tag separately or append it to ciphertext, but the database contract exposes `ciphertext`, `nonce`, `key_id` and `aad_version`.
- `phone_lookup_hmac` is HMAC-SHA-256 over canonical E.164 using a dedicated secret key. It is not an unsalted hash.

## Authoritative file-backed `ReadinessArtifact`

Readiness is deliberately not inferred from PostgreSQL or Markdown. Runtime loads an external uncommitted JSON file from `READINESS_ARTIFACT_PATH` and validates it against `contracts/readiness-artifact.schema.json` before accepting live webhooks or dispatching SMS.

| Field | Type | Rules |
|---|---|---|
| `schema_version` | integer | Exact value `1`. |
| `created_at` | RFC 3339 timestamp | Must not be in the future beyond allowed clock skew. |
| `expires_at` | RFC 3339 timestamp | Later than `created_at`, not later than `created_at + 7 days`, and later than current time. |
| `status` | string | `pass`, `fail`, or `unresolved`; only `pass` enables runtime. |
| `chatwoot` | object | Exact local URL, installed version, audited safe `version_probe`, account/inbox IDs, `hmac_supported`, and observed signing contract when supported. Unsupported HMAC cannot coexist with `status=pass`. |
| `fingerprints` | object | `hmac-sha256:<64 lowercase hex>` values for Chatwoot facts, Telnyx sender, Telnyx messaging profile and public ingress. |
| `evidence_refs` | string array | Non-secret relative paths or HTTPS references; at least one reference for every audited subsystem. |

Fingerprint inputs, fixed field ordering, normalization, live/runtime sources and deterministic vectors are defined in `contracts/readiness-fingerprints.md`. Runtime live-probes Chatwoot version/account/inbox, uses current protected Chatwoot secret and Telnyx configuration, and combines `PUBLIC_INGRESS_ORIGIN` with `PUBLIC_INGRESS_CERT_SPKI_SHA256`; it compares decoded fingerprint bytes in constant time. Artifact digest/schema version and a sanitized validation result MAY be recorded in `audit_event`; raw values, fingerprint key and full sender never are. Expiry or mismatch while a process is running immediately changes readiness to fail-closed and requires re-audit.


## 1. `webhook_inbox`

Durable queue row and permanent dedupe tombstone for provider deliveries.

| Field | Type | Rules |
|---|---|---|
| `id` | uuid PK | Internal processing ID. |
| `source` | text | `telnyx` or `chatwoot`. |
| `source_event_key` | text | Telnyx `data.id`; Chatwoot delivery ID when present, otherwise a stable audited resource/event key, falling back to authenticated raw-payload SHA-256 for generic unsupported events without a resource ID. |
| `event_type` | text | Provider event name. |
| `provider_occurred_at` | timestamptz nullable | Event occurrence time supplied by provider. |
| `payload_ciphertext` | bytea nullable | AES-GCM ciphertext; null after purge. |
| `payload_nonce` | bytea nullable | 12-byte nonce; null after purge. |
| `payload_key_id` | text nullable | Versioned secret key ID. |
| `payload_aad_version` | smallint nullable | Initially `1`. |
| `payload_sha256` | bytea | Unkeyed hash for diagnostics/equality only; never used as authentication. |
| `payload_expires_at` | timestamptz | At most receipt + 24 hours. |
| `payload_purged_at` | timestamptz nullable | Required when ciphertext is null after processing. |
| `state` | text | See state machine below. |
| `attempt_count` | integer | Starts `0`, non-negative. |
| `available_at` | timestamptz | Earliest safe retry time. |
| `lease_owner` | text nullable | Worker instance ID. |
| `lease_expires_at` | timestamptz nullable | Lease recovery boundary. |
| `last_error_code` | text nullable | Sanitized category, no provider body/content. |
| `last_error_at` | timestamptz nullable | Last processing error time. |
| `created_at`, `updated_at` | timestamptz | Managed by application/DB. |
| `completed_at` | timestamptz nullable | Terminal projection time. |

**Constraints/indexes**:

- `UNIQUE (source, source_event_key)` — durable replay protection even after payload purge.
- Claim index on `(state, available_at, lease_expires_at)` where state is queueable.
- `CHECK` ensures encrypted fields are all present or all absent.
- A purge job nulls ciphertext/nonce/key ID after terminal/manual-review state or expiry, but never deletes the row during dedupe retention.

**States**:

```text
queued -> processing
processing -> completed
processing -> retry_wait -> processing
processing -> permanent_failure
processing -> unknown_needs_review
processing --lease expiry--> queued       # only before external side-effect boundary
```

For a row whose handler crossed a non-idempotent side-effect boundary, lease expiry must produce `unknown_needs_review`, not `queued`.

## 5. `chatwoot_side_effect`

Durable commit-before-I/O ledger for non-idempotent Chatwoot create operations.

| Field | Type | Rules |
|---|---|---|
| `id` | uuid PK | Operation ID. |
| `inbound_message_id` | uuid FK | Owning inbound processing record. |
| `phone_identity_id` | uuid FK | Shared per-phone serialization key. |
| `operation_kind` | text | `create_contact`, `create_contact_inbox`, `create_conversation`, `create_message`. |
| `resource_scope_key` | text | Durable ownership key independent of worker/inbound row. Contact/conversation keys derive from phone/account/inbox/kind; message key additionally includes Telnyx message ID. |
| `stable_lookup_key` | text | Non-secret identifier used for reconciliation, such as external contact identifier or expected inbox/source tuple. |
| `state` | text | `ready`, `submitting`, `completed`, `permanent_failure`, `unknown_needs_review`. |
| `dispatch_started_at` | timestamptz nullable | Commit-before-I/O boundary. |
| `chatwoot_resource_id` | text nullable | Known contact/source/conversation/message ID. |
| `unknown_reason` | text nullable | Sanitized ambiguous-outcome category. |
| `reviewed_at` | timestamptz nullable | Manual/API reconciliation time. |
| `created_at`, `updated_at` | timestamptz | Lifecycle timestamps. |

**Constraints and behavior**:

- `UNIQUE (resource_scope_key)` is the cross-inbound creation guard. Examples: `contact:<account>:<inbox>:<phone_hmac>`, `contact_inbox:<inbox>:<phone_hmac>`, `conversation:<inbox>:<phone_hmac>`, `message:<telnyx_message_id>`.
- `UNIQUE (inbound_message_id, operation_kind)` prevents duplicate ownership records within one inbound flow.
- Before I/O, a worker inserts/claims the unique scope row and commits `ready -> submitting`. The transaction lock may be released, but no second inbound can own the same resource scope.
- A second inbound that conflicts on a contact/ContactInbox/conversation scope waits for/composes with the existing row: `completed` means reuse its resource; `submitting` or `unknown_needs_review` means do not create and defer/manual-review; `permanent_failure` follows explicit retry/reconciliation policy without a second ambiguous dispatch.
- A known 2xx stores the resource ID and completes the operation.
- Timeout/reset/process death after dispatch becomes `unknown_needs_review`; restart never repeats the create blindly.
- Reconciliation may query by stable contact identifier, ContactInbox source/inbox tuple, or conversation/contact/inbox relationship. It may attach a uniquely proven existing resource and mark `completed`; zero or multiple candidates remain manual review.
- `create_message` is additionally reflected by `inbound_message.chatwoot_submitting`; both records complete atomically with the returned Chatwoot message ID.

This ledger plus the per-phone advisory lock prevents a crash after external creation but before local binding commit from causing a second contact/conversation/message creation.

## 6. `inbound_message`

Durable inbound processing boundary and complete FR-006 correlation chain.

| Field | Type | Rules |
|---|---|---|
| `id` | uuid PK | Bridge processing record ID. |
| `webhook_inbox_id` | uuid FK | Unique Telnyx receipt row. |
| `phone_identity_id` | uuid FK | Canonical sender identity. |
| `telnyx_event_id` | uuid | `data.id`. |
| `telnyx_message_id` | uuid | `data.payload.id`. |
| `state` | text | State machine below. |
| `chatwoot_dispatch_started_at` | timestamptz nullable | Commit-before-message-create boundary. |
| `chatwoot_contact_id` | bigint nullable | Stored when resolved. |
| `chatwoot_conversation_id` | bigint nullable | Stored when resolved. |
| `chatwoot_message_id` | bigint nullable | Stored only after known success/reconciliation. |
| `content_sha256` | bytea | Diagnostic correlation hash only. |
| `unknown_reason` | text nullable | Sanitized ambiguous-outcome category. |
| `reviewed_at` | timestamptz nullable | Manual reconciliation time. |
| `review_outcome` | text nullable | `found_created`, `confirmed_not_found`, `unresolved`. |
| `created_at`, `updated_at`, `terminal_at` | timestamptz | Lifecycle timestamps. |

**Constraints/indexes**:

- `UNIQUE (webhook_inbox_id)` and `UNIQUE (telnyx_event_id)`.
- `UNIQUE (telnyx_message_id)` for this SMS-only inbound scope.
- `chatwoot_message_id` unique when non-null.
- `completed` requires all Chatwoot IDs.
- `unknown_needs_review` requires `chatwoot_dispatch_started_at` and `unknown_reason`.

**State machine**:

```text
received -> ready
ready -> resolving_chatwoot
resolving_chatwoot -> ready                 # only proven pre-dispatch safe retry
ready -> chatwoot_submitting                # commit before HTTP I/O
chatwoot_submitting -> completed            # response supplies message ID
chatwoot_submitting -> permanent_failure    # explicit deterministic rejection
chatwoot_submitting -> unknown_needs_review # timeout/reset/ambiguous response/crash
unknown_needs_review -> unknown_needs_review # review annotates only; no automatic create retry
```

Duplicate Telnyx deliveries resolve this record and return its stored outcome. They never create another Chatwoot message.

## 8. `suppression_current`

Materialized/application-maintained current guard state.

| Field | Type | Rules |
|---|---|---|
| `phone_identity_id` | uuid PK/FK | One state per phone. |
| `state` | text | `active`, `clear`, `opt_in_claimed_needs_review`. |
| `last_event_id` | uuid FK | Event that produced current state. |
| `effective_at` | timestamptz | State effective time. |
| `updated_at` | timestamptz | Projection time. |

**Projection rules**:

- Creating `phone_identity` atomically appends one `identity_initialized_clear` event and creates `suppression_current(state=clear,last_event_id=<that event>)`; this initialization event is legal only as the first event for that identity.
- Absence of the current row or initialization event is a data-integrity error and blocks outbound.
- `opt_out`, `operator_suppress`, `provider_block_observed` → `active`.
- `opt_in_claimed_needs_review` keeps outbound blocked.
- This slice has no transition back to `clear` after opt-out; a future specification must define any confirmed opt-in flow.

**State machine**:

```text
received -> blocked_suppressed
received -> recipient_mapping_needs_review
received -> rejected_invalid

accepted|sent -> delivery_failed
accepted|sent -> delivery_unconfirmed
```

## Transaction boundaries

### Webhook receipt

Single transaction:

1. insert `webhook_inbox` encrypted row using unique source identity;
2. insert audit metadata for accepted/duplicate;
3. commit;
4. return 2xx.

Invalid signature/timestamp is rejected before any payload insertion; a safe signature-rejection audit may be written without request body.

### Per-phone serialization and suppression ordering

Every consent projection, contact/conversation resolution and outbound claim acquires the same PostgreSQL transaction advisory lock derived from `phone_identity_id`, then locks the persistent `phone_identity` and `suppression_current` rows. Actions for that phone are evaluated by provider occurrence time followed by durable receipt order. Before an outbound claim, the worker projects every earlier queued STOP-family event already durably received for that phone.

The transaction advisory lock serializes only local mapping resolution and the durable claim of a `chatwoot_side_effect.resource_scope_key`; it is released when the `submitting` claim commits before HTTP I/O. Crash/concurrency safety across HTTP comes from the globally unique committed resource scope: another inbound cannot claim/create the same contact, ContactInbox or conversation and must reuse, defer or require review according to the existing operation state.

### Outbound guard and submission claim

Single transaction before network I/O:

1. acquire shared per-phone advisory lock; lock `phone_identity`, mandatory `suppression_current`, and `outbound_send`;
2. project any earlier durably received consent event for this phone;
3. if state row is absent/corrupt or blocked, set fail-closed outcome and commit;
4. otherwise require state `ready`, set `submitting`, `submission_count=1`, timestamp and commit;
5. perform one Telnyx call outside transaction.

### One-time operator smoke claim

After preliminary readiness/GSM-7 checks and typed confirmation, one final transaction:

1. acquires the global smoke advisory lock and shared per-phone advisory/row locks;
2. reloads/revalidates the same readiness artifact digest and current environment fingerprints;
3. projects earlier durable consent events and locks mandatory `suppression_current` plus sender/profile guard state;
4. on any failure, rolls back without inserting `smoke_test_run` or `outbound_send`, so the global allowance is not consumed;
5. otherwise inserts the globally unique `smoke_test_run`, creates one `outbound_send` directly in `submitting`, sets `submission_count=1` and commits the submission boundary atomically;
6. performs exactly one Telnyx call outside the transaction. Any crash/ambiguity after commit consumes the allowance and becomes `unknown_needs_review` without retry.

A suppression event received after the committed claim is ordered after that already-authorized attempt; an earlier durable STOP is always projected before the claim.

### Payload purge

After business projection reaches terminal/manual-review:

1. store all non-content correlation/status metadata;
2. null ciphertext/nonce/key ID and set `payload_purged_at`;
3. commit atomically.

A TTL sweeper applies the same purge to expired queued rows and marks them `permanent_failure`; this feature has no incident-hold exception. It never silently deletes dedupe identity.

## Export contracts

Both exports require an explicit operator-selected protected file destination. Stdout is not a destination, exported rows are never logged, and path/permission checks fail closed before writing.

### Suppression export

The privileged export process joins `phone_identity`, `suppression_current`, and the latest suppression evidence, decrypting canonical phone only in-process. Minimum columns:

```text
phone_number,suppression_state,effective_at,source,last_event_id
```

Chatwoot contact deletion/merge does not remove this bridge-owned suppression data.

### Metadata-only correlation export

The correlation export joins `webhook_inbox`, `inbound_message`, `outbound_send`, `provider_event_projection`, `smoke_test_run`, and safe binding IDs as applicable. It does not decrypt or emit canonical phone and includes only allowlisted fields such as:

```text
bridge_record_id,source_event_id,event_or_action_type,telnyx_message_id,chatwoot_account_id,chatwoot_inbox_id,chatwoot_conversation_id,chatwoot_message_id,chatwoot_ids_applicability,status,outcome,masked_phone,received_at,completed_at
```

Rules:

- inbound and Chatwoot-originated fixture evidence require the applicable local Chatwoot IDs;
- for `origin=operator_smoke`, all Chatwoot ID columns are `null` and `chatwoot_ids_applicability=not_applicable`;
- no row contains SMS body, content hash presented as content, raw payload, full phone, credential, secret, encryption material, or raw provider response;
- deletion of a local Chatwoot contact does not remove bridge-owned correlation metadata.
